# ADR 0003 — M3 implementation choices

Status: accepted · 2026-09-14

These refine the approved plan (docs/00–10) for M3 (team features) where it left details open.

| # | Decision | Why |
|---|---|---|
| 1 | **Network Doctor logic is a pure function** (`NetworkDoctor.evaluate`) fed by live inputs: network state, listen port, mDNS services seen in a 4 s window, connected peers and a direct dial to up to 3 contacts' last addresses. | Unit-testable without sockets. Unicast-works-but-mDNS-silent separates "multicast blocked" (N4) from "client isolation" (N3). |
| 2 | **OS checks go through `PlatformDiagnostics`** in `Platform`: Windows network profile (`Get-NetConnectionProfile`) and firewall rule on desktop, battery-optimization exemption on Android. Fixes either apply directly (firewall, UAC prompt) or open the right settings page, then the check reruns when the user returns. | Keeps OS code in the shells; core stays common. |
| 3 | **Virtual adapters are reported, not selectable.** Network Doctor shows the adapter in use and the ignored virtual adapters (N20). | Discovery and ICE already skip virtual adapters; a picker adds settings nobody needs so far. Revisit if a real network needs it. |
| 4 | **Android asks for the battery-optimization exemption directly** (`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`), falling back to the system list. | Zoocall has no push service; an incoming LAN call can only ring if the app isn't dozed. This is an accepted Play policy use case. |
| 5 | **Knock uses envelope field 50** as `Knock{id, text, in_reply_to, reply}` with a fixed reply enum (Call me / 2 min / Busy). `reply_options[]` from docs/03 is not implemented. | Localized fixed replies read correctly on both sides; free-form options would arrive in the sender's language. |
| 6 | **Knocks are live only**: not stored, not queued; a knock to an unreachable peer fails immediately. Replies are accepted only for our own knocks from the last 10 minutes. Limits: 1/min from strangers, 5/min from contacts. DND shows knocks from non-favorites without sound. | A knock asks "are you free now?"; a late one is noise. |
| 7 | **Desktop system notifications** (tray) for knocks and messages while the main window is hidden or minimized. Their text is English for now. | The desktop shell had no message notifications. Shared resources (`Res`) are internal to `:shared:ui`; the shell's tray menu is English too. Localizing the shell is part of the M4 strings work. |
| 8 | **Ringtones:** Android uses the system ringtone picker and stores the URI (deleted tones fall back to the default); desktop offers three synthesized tones (classic, gentle, bright) with preview, plus Silent. **Flash alert** blinks a white overlay on the ringing call screen once a second (below the WCAG 2.3.1 three-flash limit) and, on phones, the camera light. "Call sounds" gates connect/end tones, call-waiting beeps and knock chimes. | No bundled audio files or network; the system picker is the familiar Android pattern. |
| 9 | **Push-to-talk reuses the call pipeline**: `CallInvite.push_to_talk` opens an audio session that the callee auto-accepts (no ringing state at all) when it allows PTT from that contact; the mic stays off except while talking. Floor control is `PttFloor` (envelope field 52) on the Noise control channel, not a WebRTC data channel as docs/03 §4.5 suggested. The session opens when the user starts PTT rather than staying armed in the background. | Keeps one media and signaling path (Telecom, foreground service, reconnect, stats all work), and avoids adding data channels to two WebRTC stacks. The control channel is already authenticated, ordered and low-latency on a LAN. |
| 10 | **Push-to-talk is opt-in per contact** (`contact.allow_ptt`, migration v4) and follows DND like calls (favorites still connect). Ties on simultaneous talk: the caller keeps the floor in 1:1, the earliest joiner in a group channel. Loudspeaker unless a headset is connected; start/stop chirps always play. A group channel is a group call with `push_to_talk`; joining it through the host means hearing everyone in it. | Auto-connecting audio must never surprise someone who didn't agree to it. |
| 11 | **Global mute hotkey uses Win32 `RegisterHotKey`** (through the existing JNA dependency) instead of JNativeHook, registered only while a call is live, Windows only for now. A short falling/rising cue confirms mute/unmute. | `RegisterHotKey` receives only the one combination, never other keystrokes, and needs no new native library. Registering only during calls avoids stealing Ctrl+Shift+M from other apps the rest of the time. macOS needs a Carbon/`NSEvent` implementation and a Mac to test; it comes with the Mac work. |
| 12 | **Group calls reuse the 1:1 leg machinery.** Every remote person is a media leg; the state machine follows one leg (whoever we called or who called us) and the others are `members`. If that leg ends, a connected member takes its place (C22). The host (caller, then earliest joiner) sends `CallRoster` with hex fingerprints and host-seen addresses after each join; for each pair the lower fingerprint dials and offers, and SDP/ICE that arrive before a leg exists are buffered. Only the host adds people; hold and video upgrade are off in groups. | One tested call engine instead of a second one for groups; a deterministic offer direction needs no extra negotiation messages. |
| 13 | **The media engines share one camera capture across legs** (reference-counted; capture runs while any leg wants video), and each leg gets its own track from that source. Screen capture is shared the same way. | A camera can only be opened once, and the OS camera light must follow the user's camera button in every leg. |
| 14 | **Screen sharing (desktop → everyone)** replaces the camera track on its sender in video calls; in audio calls the sharer adds a video track and renegotiates itself. Either side may renegotiate after the first exchange, and a failed renegotiation no longer ends a call. Stopping keeps the video section. Screens and windows are picked from a list (titles, no thumbnails). | No consent step is needed to show your own screen, and no second media path. Offer glare is rare on a LAN and harmless now. |
