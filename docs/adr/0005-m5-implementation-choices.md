# ADR 0005 — M5 implementation choices

Status: accepted · 2026-09-14

These refine the approved plan (docs/00–10) for M5 (stand-out features) where it left details open.

| # | Decision | Why |
|---|---|---|
| 1 | **Contact groups are local only** (`contact_group`, `contact_group_member`, migration v6). Calling or push-to-talk to a group calls the first reachable member, then adds the others through the existing group-call invitation once connected. | Nothing new on the wire and nobody learns how you label them. Group calls already handle joining, host transfer and limits. |
| 2 | **Announcements are chat messages with `announcement = true`** (`chat.announce`), sent 1:1 to every member through the normal outbox, so offline members get them later. Receivers alert once even in the foreground (Android high-importance channel, desktop tray notification + chime) and quietly in Do Not Disturb except for favorites. Text or a voice clip. | Reuses delivery, receipts, storage and search; older clients still show the text. |
| 3 | **Private discovery ("Contacts only")** advertises no name, role or fingerprint, only `t=` tags: 4 bytes of keyed BLAKE2b(pair secret, 10-minute epoch) for up to 16 contacts (favorites, then most recently seen), where pair secret = BLAKE2b(context ‖ X25519(our static key, their static key)). The mDNS instance name also rotates each epoch. Receivers match the previous, current and next epoch against their contacts and hide unmatched private advertisements. | Same property as the planned HMAC-SHA-256 (docs/03 §2, docs/04) with the BLAKE2b MAC libsodium already provides. No extra key exchange: the pair secret follows from the identity keys contacts already verified. |
| 4 | **Live captions use the operating system's on-device captioning** (Windows 11 Live Captions, Android Live Caption, macOS Live Captions), opened from the call's More menu and Settings. No speech model ships with Zoocall. | The OS captioners run fully on-device, already support calls and many languages, and are maintained with accessibility users. Bundling an offline ASR model would add tens of MB per platform (APK budget < 30 MB) and a second audio pipeline. |
| 5 | **Noise suppression and background blur:** desktop offers libwebrtc's strongest noise suppression level as an opt-in setting (through our own `AudioProcessing` module); the ML effects themselves come from the OS (Windows Studio Effects, macOS Voice Isolation / Portrait, OEM effects on Android), with a Settings shortcut on Windows. | OS effects are hardware-accelerated and apply to the camera and microphone before Zoocall sees them. Shipping our own segmentation and RNNoise models would blow the size budget and double work the OS already does. |
| 6 | **Linked devices are mutual claims, not a shared key** (`device.link`, contact column `linked`, migration v7). The user turns on "This is my device" for a *verified* contact on both devices; each lists the other in `Hello.linked_devices`. Callers ring the callee plus its mutually linked devices with one `call_id`; the first answer wins and the rest get `CallCancel.handled_elsewhere`. Contacts, chats and "Allow calls from" stay per device. | Keeps the plan's "private key never leaves the device" rule (edge case D2) and needs no new crypto: both claims travel over authenticated Noise channels, which is what a signed device list proves. Syncing contacts and chats between devices would be a replication system of its own; not needed to ring together. |
| 7 | **Desk intercom is a call flag, not a new call type** (`CallInvite.intercom`, `call.intercom`, contact column `allow_intercom`). Receiving is desktop-only: a "Desk intercom" setting (off by default) plus "Allow intercom" per contact; Do Not Disturb always refuses, even favorites. Any device can start one to a computer. Lines are audio-only, 1:1, show a "microphone is on" banner and chime on both ends, and appear in Recents. | Reuses the push-to-talk auto-accept path and the normal audio call screen, so reconnection, mute and hang-up behave like any call. Two opt-ins and a chime answer edge case H3 (silent listening). |
| 8 | **Disappearing messages travel per message** (`ChatMessage.expires_in_s`, `chat.disappear`, column `message.expires_at_ms`). The timer is a per-conversation setting; a supporting peer adopts the value on each message, and a 30-second sweep deletes expired rows with their voice clips and attachment files. Timers start at send (sender) and at arrival (receiver). No separate "timer changed" control message. | Per-message values need no extra sync state and survive offline outboxes; adopting from messages matches how people expect the setting to follow the chat. Starting the receiver's timer on arrival keeps late deliveries readable. |
| 9 | **App lock uses the device's lock on Android and an app passcode on desktop.** Android shows the system `BiometricPrompt` (fingerprint/face or the screen lock; the lock screen's own confirmation on Android 9) and needs `USE_BIOMETRIC`. Desktop stores only an Argon2id hash (libsodium `crypto_pwhash_str`), with 5 tries then a 30-second wait. The app locks at start and after a minute out of sight; the unlocked state lives in process memory only. Calls keep ringing and can be answered while locked because they use their own activity/window. | Windows Hello and Touch ID have no JVM API without large native bridges; the plan already calls for an Argon2id app passphrase where no OS store exists (docs/04). Not composing the locked UI keeps it away from screen readers and keyboard focus. |
| 10 | **Encrypted export is a protobuf payload in a chunked, passphrase-sealed file** (`.zcbackup`, protocol/spec/backup-file.md): Argon2id (ops 3, 64 MiB) key, 64 KiB ChaCha20-Poly1305 chunks with a last-chunk flag in the nonce. It carries profile, contacts (with public keys), groups, and text and voice messages; not the identity key, files or disappearing messages. Restore is offered in Settings and during onboarding, merges by id and never overwrites existing contacts. | Reuses libsodium primitives and the chunking already used for attachments at rest; protobuf gives a versioned format with the same compatibility rules as the protocol. Leaving the key out is the plan's rule (D2); leaving files out keeps backups small enough to move easily. |
| 11 | **Group chats are sender fan-out with the group in every message** (`ChatMessage.group`, `chat.group`; tables `group_chat`, `group_recipient`; `message.group_id`). Each group message is stored once and queued per member in the existing outbox flush; receipts advance each member's row. Receivers create or update the group from messages (newest `updated_at_ms`, changed only by current members). Started from a contact group's "Chat" action; members can leave. Text and voice notes only. | The plan's "mesh fan-out from sender, queued per member" (docs/01 §5, M11) with no group server or key agreement: every copy already travels over an authenticated Noise channel. Carrying the group in each message keeps members in sync without extra control messages. Files, reactions and timers are left out to keep the first version small. |
| 12 | **Android shares the whole screen with MediaProjection** through libwebrtc's `ScreenCapturerAndroid`, using the same `call.screen` signaling as desktop (replace the camera track in video calls, add a track and renegotiate in audio calls). Each share asks for the system's consent; the call's foreground service adds the `mediaProjection` type first (`FOREGROUND_SERVICE_MEDIA_PROJECTION`), and the system's own "Stop sharing" ends the share for everyone. One capture serves every leg of a group call. | The system prompt and status-bar cast icon are Android's honest, required indicators; whole-screen capture avoids an in-app picker Android can't populate. Reusing the desktop flow means receivers need no changes. |
| 13 | **Attended call transfer is "add them, then leave"** on the group-call machinery (`call.group`): whoever is in a 1:1 call may add a person and becomes the host (so the person who *answered*, e.g. a front desk, can transfer), and `transferTo` hangs up automatically once the new person's media leg connects. If they decline or don't answer, the call stays as it was. The other person hears the handover live, with no hold music or blind drop. | No new protocol messages: roster, host transfer and member promotion already exist and are tested. A consult-then-merge flow with two separate calls would need a second active call, which the call state machine deliberately doesn't allow. |
| 14 | **Call recording is audio-only, local and announced** (`MediaState.recording`, `call.record`). It needs every participant to support `call.record`; everyone sees a banner and hears a chime, and the recorder confirms first. libwebrtc `AudioTrackSink`s on our microphone and the remote track feed a mixer (16 kHz mono, the voice-note Opus codec), streamed into the attachment at-rest format with a key kept in the call log. Recents offers "Save recording" as a WAV copy. At most 2 hours. | Meets the plan's "can't start silently" rule (docs/04, H6) with no server and no new codec. Audio-only keeps files small and avoids per-platform video muxing; WAV export plays everywhere without shipping an Ogg muxer. |
